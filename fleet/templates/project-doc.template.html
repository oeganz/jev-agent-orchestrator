Overview

This is the fleet's canonical document. It exists so an AI can write the first draft and a human can audit it claim-by-claim. Every inline phrase tagged with class claim carries an id, a source, and an evidence pointer path:line.

The doc is one file: fleet/bin/fleet.mjs hosts the CLI entry point, and the helpers live under fleet/bin/lib/cascade.mjs.

Replace these placeholders with your project. The contract stays the same: one doc-meta JSON block, claim tags with class claim + data-claim + data-source + data-evidence, and a sidebar with at least Overview / Architecture / Flows / Reference pages.

Stack

The doc is one static HTML file. It loads two CDN scripts: Mermaid for diagrams and svg-pan-zoom for panning. No build step, no deps.

Token system

The visual language is the same as the reference: :root CSS variables with a dark default and a [data-theme="dark"] override.

Data

Claims come from the doc. Reviews are stored in localStorage keyed by project + doc_version and exported as a JSON file the human can hand back to the AI.

Human review flow

  1. Toggle Review in the header.
  2. Click any claim: pick agree, wrong, or unsure; add a note.
  3. Watch the summary bar at the top fill in.
  4. Export the review as JSON to share with the AI author.

Export / import

Export writes a JSON file with shape {project, doc_version, reviewer, reviewed_at, reviews[]}. Import reads the same file and merges into localStorage.

Reference

Claim schema

  • data-claim: stable id (required).
  • data-source: code | config | doc | inferred.
  • data-evidence: path:line or path:line-line (required unless inferred).

Doc meta

A <script type="application/json" id="doc-meta"> block with project, doc_version, generated_by, generated_at, commit.
